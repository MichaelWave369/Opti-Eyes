# Rung 6 / Optical Prototype Bench

## Purpose and limitation

This is an instrument-free **bench test planning and recordkeeping tool**, not a prototype measurement system. It records two different evidence sources: **synthetic** (deterministic examples generated by code) and **user-reported** (manual entries whose provenance and accuracy the software does not independently verify). They are never silently promoted to verified data.

## Example research criteria

Default **illustrative, user-editable** checks:
- Absolute focus power discrepancy: at most 0.25 D.
- Reported settling time: at most 300 ms.
- Reported optical drift: at most 0.10 D.

These are not derived from a product standard, optical prescription, acceptable wearer performance, clinical evidence or device safety requirement. They are comparison knobs and can be changed. The criteria are inclusive and all three must hold for the label **WITHIN USER CRITERIA**. The label is NOT PASS, safe, wearable or certified.

Six synthetic examples are loaded by default. Three are within and three outside the default criteria. They are demonstrative values invented for the training fixture, **not measurements or vendor specs**. The selected optical mechanism from Rung 4 is captured with new entries, and changing that mechanism never rewrites prior records.

## Manual data entries

A manual trial includes target diopters, user-reported observed diopters, settling milliseconds, drift diopters, an instrument/source identifier, method/reference description and optional notes. There is no direct device access; entries are always **USER ENTRY / UNVERIFIED**. Input fields are bounded. A 200-record cap protects the browser session. No persistence, telemetry, account, cross-site I/O or transmission. Export before reloading.

## Exports

- JSON carries unverified status and source labels, user criteria, individual checks, provenance, and explicit `eyeSafetyValidated:false` / `observationsVerified:false` flags.
- CSV carries the same classifications and source labels. Free-text fields are neutralized if they begin with spreadsheet formula characters to reduce CSV injection risk. It is still untrusted research data.

Exports are initiated only when the user clicks the associated button.

## Actual bench work that remains

Real optical research requires calibrated instruments, traceable reference standards, measured optical-power curves across lens travel and distance, repeatability and hysteresis, full-aperture aberrations/distortion, optical clarity, occlusion/sensor fault tests, and validated loss-of-power states. The team must document the experimental procedure, environmental conditions, references, timestamps, instrument serial/model numbers, uncertainties and independent reviewers.

Real wearability requires additional qualified optical/medical fitting, electrical and material testing, impact/UV protection assessment where applicable, and regulatory work. This software does not provide instructions to wear a printed frame or actuate unverified optics around eyes.

## Acceptance

Run `npm run check && npm run build`. Inspect UI with six default examples, vary each threshold and ensure the counts change; add manual entries and verify they remain USER ENTRY / UNVERIFIED; clear memory, reload demos, export both formats. Rungs 1–5 must remain intact.
